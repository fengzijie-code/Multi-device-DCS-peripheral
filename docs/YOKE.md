# 手机当摇杆

手机倾斜 → 飞机响应。这一页把整条链路、需要装什么、以及在 DCS 里怎么绑轴讲清楚。

```
手机传感器 ──HTTP POST /input──> beacon.py ──UDP :5011──> vjoy_out.py ──vJoy──> DCS
   (50 Hz)                        (桥接)                       (虚拟摇杆)      (DirectInput)
```

前四跳都已经实现并验证过：手机端稳定 50.0 Hz，单帧往返 3 ms，看门狗 531 ms 回中。
**只有最后一跳依赖 vJoy 驱动**，需要装一次。

---

## 一、为什么绕不开 vJoy

DCS 的飞行模型只从 DirectInput 设备读操纵轴。`Export.lua` 能读数据、能点座舱按钮，
但**没有任何接口可以直接写操纵面**。所以要控制飞机，必须先让 Windows 里出现一个
「假的手柄」，由 DCS 当作真实设备去读。

这是整条链路上唯一需要装驱动的地方，也是一次性的。

### 安装步骤

1. 右键 `.tmp/vjoy/vJoySetup.exe` → **以管理员身份运行**（不带管理员权限装不上驱动）。
2. 装完**重启一次**。驱动是内核态的，不重启不生效。
3. 开始菜单搜 **Configure vJoy** 打开配置：
   - 勾选 **Device 1**
   - 至少勾上 **X** 和 **Y** 两根轴，范围保持 0–32767
   - 点 **Apply**，再点 **Reset**（确认能写进去）
4. 打开「设置 → 蓝牙和其他设备 → 设备」，应该能看到一个 **vJoy Device**。

### 会有什么副作用

安装后系统里会多一个游戏控制器。对 DCS 的影响很小——DCS 按设备名+GUID 记住绑定，
新设备只是多出一列，不会打乱已有的物理摇杆/油门绑定。

但如果你的物理摇杆是**按顺序号**被别的软件识别的（少数老工具会这样），编号可能变化。
真遇到这种情况，在设备管理器里禁用 vJoy 就能恢复。

## 二、启动

```bat
tools\start-usb.bat
```

会开四个窗口，其中 `dcs-vjoy` 就是虚拟摇杆输出。它启动时的第一件事是**自检驱动**：

| 窗口里的提示 | 说明 |
|---|---|
| `虚拟摇杆输出 Device 1 vJoyInterface = C:\...\vJoyInterface.dll` | 正常 |
| `找不到 vJoyInterface.dll` | 没装 vJoy，或装完没重启 |
| `vJoy 驱动没在跑` | 装了但驱动没起来；开始在菜单里跑一次 Configure vJoy |
| `Device 1 不存在` | 驱动在，但没在 Configure vJoy 里启用设备 1 |
| `Device 1 被别的程序占用` | 上一次的 vjoy_out.py 没退干净，或 Configure vJoy 还开着 |

手机端不用额外配置——桥接起来以后，摇杆页顶部会自动显示
**「PC 端虚拟摇杆就绪」**（灰点是绿的就说明五个进程都在）。
显示「未运行 · 杆不会动」就说明 `dcs-vjoy` 那个窗口没起来。

## 三、在 DCS 里绑轴

**先启动 DCS**（vJoy 必须在 DCS 启动前就存在，DCS 只在启动时枚举设备）。

1. `设置 → 操控 → 选中你的机型 → 轴命令`
2. 找到 **Pitch**（俯仰）→ 点它右侧 **vJoy Device** 那一列的格子
3. 这时**倾斜手机**（先在手机 App 里点「校零」再「解锁」），DCS 会自己识别到轴
4. 同理绑定 **Roll**（横滚）
5. 点 **轴调整**，把这个轴的 **死区设为 0、曲率设为 0**

第 5 步很重要。死区和曲线已经在手机端做了（可以实时调），DCS 里再叠一层会让
手感变成两个曲线的乘积，中间会非常钝，而且两边都调不出想要的效果。

> 方向反了怎么办：先试手机端摇杆页的「左右 翻转 / 前后 翻转」，那是最快的一层。
> 也可以在 DCS 的轴调整里勾 Invert，但建议只在一处翻转，否则以后排查会绕晕。

## 四、调手感

摇杆页右下三个参数，改完立刻生效并持久化：

| 参数 | 默认 | 含义 | 怎么调 |
|---|---|---|---|
| **行程** | 22° | 打到满杆要倾斜多少度 | 觉得太灵敏/容易过量就调大；觉得转不动就调小 |
| **死区** | 2.5° | 中位附近多大范围内算「没动」 | 手放上去杆就自己抖，就调大；觉得中位黏滞就调小 |
| **曲线** | 0.35 | 0 = 线性，1 = 纯三次方 | 调大：中位更细腻、大杆量仍能到满。空战狗斗建议 0.4–0.6 |

还有两个开关：

- **横握 / 竖握** —— 决定「左右倾斜」对应设备哪根轴。横屏拿着手机就选横握；如果发现
  推左右变成推前后，就是这里选反了。
- **左右/前后 翻转** —— 方向反了先动这里。

左边那块「杆位盘」是调参时的眼睛：绿点就是当前杆位，网格是半杆位置。
**死区调得合不合适，看静止时绿点抖不抖就知道了。**

## 五、安全机制

手机当摇杆最大的风险不是延迟，是**它会在你不知情的时候继续输出**。
vJoy 是状态保持的：写进去一个杆位，即使写它的程序被杀掉，那个值也会一直留着。

所以做了三层，互相独立：

| 层 | 触发条件 | 动作 |
|---|---|---|
| **解锁** | 默认是锁的 | 不发任何操纵量，只发 0 |
| **手机端自动上锁** | 连续 3 帧发送失败 / 倾角超过阈值 400 ms | 立刻发 0 并上锁，界面变红 |
| **PC 端看门狗** | 500 ms 没收到新操纵量 | 把杆回中 |
| **退出归零** | Ctrl+C、关窗口、注销 | 先 `ResetVJD` 再释放设备 |

为什么「发送失败要自动上锁」而不是继续重试：链路恢复的瞬间，如果飞机还停在断线前
那个舵量上，会突然满杆回弹——那比失控更危险。上锁以后必须人工再点一次，
虽然麻烦，但这是唯一不会让人措手不及的做法。

**手机掉了/放桌上**：倾角超过 `max(55°, 行程×1.8)` 持续 400 ms 会自动上锁。

**救急**：`python tools/vjoy_out.py --reset` 强制回中并释放设备。

## 六、排障

先看手机摇杆页顶部那行字，它能直接定位断在哪一跳：

| 现象 | 断点 | 处理 |
|---|---|---|
| 「未设置服务器地址」 | 没配地址 | 点右上「设置」，填 `http://127.0.0.1:8080` |
| 底部链路显 `0ms 0.0Hz` | 桥接没起 / adb reverse 掉了 | 看 `dcs-watchdog` 窗口；手动 `adb reverse tcp:8080 tcp:8080` |
| 链路正常但「虚拟摇杆未运行」 | vjoy_out.py 没跑 | 看 `dcs-vjoy` 窗口的报错 |
| 「虚拟摇杆就绪」但飞机不动 | DCS 没绑轴，或 vJoy 在 DCS 启动后才装 | 重启 DCS，重新绑轴（见第三节） |
| 飞机自己往一边偏 | 没校零，或校零后换了握姿 | 重新「校零」；确认静止时杆位盘绿点在中心 |
| 杆量方向反了 | 轴方向 | 用「左右/前后 翻转」 |
| 推左右变成推前后 | 握法 | 切「横握 / 竖握」 |

如果手机端显示「发送失败，已自动上锁」：那是网络真的断了（连续 3 帧，
单次抖动不会触发）。检查 USB 线、`adb reverse`、以及 `dcs-beacon` 窗口是否还活着。

## 七、已知限制

- **只有两根轴**。油门、脚舵还没做——脚舵用手机偏航（rotvec 的第三个分量）
  技术上现成，但没有回中反馈，建议留给实体踏板。
- **绝对位置映射，不是速度映射**。手停在某个角度 = 杆停在某个位置。
  这和真实驾驶杆一致，但长时间保持大杆量会比较累。
- **会漂移**。`TYPE_GAME_ROTATION_VECTOR` 不融合磁力计（避免室内磁干扰），
  代价是零漂，大约几分钟几度。觉得杆位跑偏了就再点一次「校零」。
- **后台自动上锁**。App 一进后台就停手，这是刻意的——系统会限流后台传感器，
  继续挂着解锁状态会保持住最后一帧的舵量。
