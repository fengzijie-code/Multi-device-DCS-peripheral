# 手机遥控台

手机倾斜 + 触摸 → 飞机响应。这一页把整条链路、需要装什么、以及在 DCS 里怎么绑讲清楚。

```
手机传感器/触摸 ──HTTP POST /input──> beacon.py ──UDP :5011──> vjoy_out.py ──vJoy──> DCS
      (50 Hz)                          (桥接)                      (虚拟摇杆)      (DirectInput)
```

前四跳都已实现并实测：**50.0 Hz、单帧 3 ms、看门狗 531 ms 回中**。
最后一跳依赖 vJoy 驱动，装一次即可。

---

## 启动（开机后只跑这一个）

双击 **`tools\start-usb.bat`**。重启电脑后也只跑它。

它依次做三件事，每一步都打印结果：

```
[1/3] 检查 adb 与手机 …        ✓ 设备 35311JEGR07ZVC
[2/3] 建立 USB 隧道 …          ✓ tcp:8080 -> tcp:8080
[3/3] 启动服务 …
```

然后在一个窗口里同时跑三个进程，输出按标签分开：

| 标签 | 进程 | 干什么 |
|---|---|---|
| `[beacon]` | beacon.py | HTTP :8080 + 遥测 UDP :5010 |
| `[watch ]` | usb-watchdog.py | 每 2 秒重建 `adb reverse`，每 30 秒报一次心跳 |
| `[vjoy  ]` | vjoy_out.py | 手机操纵量 → vJoy 驱动 |

某个进程意外挂掉会自动重启（同一分钟内最多重试 3 次）。
**Ctrl+C 或关窗口 = 全部停止**，而且会先让杆回中。

要开假遥测（没有 DCS 时联调用）：`start-usb.bat mock`。

### 开机后要重跑什么

| 东西 | 重启后 |
|---|---|
| vJoy 驱动 | 还在，不用重装 |
| 手机 App | 还在，不用重装 |
| `adb reverse` 隧道 | **会丢**，启动器负责重建 |
| 三个 Python 服务 | **要重跑**，就是 `start-usb.bat` |

### 想分开调试

每个服务都能单独跑：

```bat
python tools\beacon.py --port 8080 --ipv4-only
python tools\usb-watchdog.py --interval 2
python tools\vjoy_out.py                 :: 加 --dry-run 可以不接驱动
python tools\run-all.py                  :: 启动器本体
```

## 一、通道一览

| 手机操作 | 通道 | vJoy | 类型 | 在 DCS 里绑到 |
|---|---|---|---|---|
| 左右倾斜手机 | `x` | **X** | 回中 | Roll（横滚） |
| 前后倾斜手机 | `y` | **Y** | 回中 | Pitch（俯仰） |
| **脚舵滑块**（杆位盘下面那条）或**拧手机** | `r` | **Rz** | 回中 | Rudder（脚舵） |
| 左侧竖条上/下划 | `t` | **Z** | **保持** | Throttle（油门） |
| 右上「视角」区按住拖动 | `vx` / `vy` | **Rx** / **Ry** | 回中 | View Horizontal / Vertical |
| 襟翼↑ / 襟翼↓ / 起落架 | `b` | **Btn 1/2/3** | 按键 | 各自的命令 |

「回中」= 松手归零；「保持」= 松手停在原地。这个区别决定了断线时它们各自的
行为，见第五节。

### 脚舵有两个来源

- **滑块**（推荐入门）：杆位盘下面那条横的，按住往左/右压，松手回中。
  看得见、控得住，落地侧风修正时能一直压着。
- **拧手机**：横握时绕屏幕法线转手腕。更接近真机的连续感，但**看不见**，
  而且横滚时手腕会带出多余偏航（物理耦合，软件只能淡化）。

两者**不叠加**：手指按在滑块上时以滑块为准，松开就交还给拧动。
不想要拧动的话，校准页把「拧手机」关掉即可 —— 滑块不受影响。

## 二、为什么绕不开 vJoy

DCS 的飞行模型只从 DirectInput 设备读操纵轴。`Export.lua` 能读数据、能点座舱按钮，
但**没有任何接口可以直接写操纵面**。所以要控制飞机，必须先让 Windows 里出现一个
「假的手柄」，由 DCS 当作真实设备去读。

这是整条链路上唯一需要装驱动的地方，也是一次性的。

### 安装步骤

1. 在项目根目录找到 **`vJoySetup.exe`**，右键 → **以管理员身份运行**
   （不带管理员权限装不上驱动）。
2. 装完**重启一次**。驱动是内核态的，不重启不生效。
3. 开始菜单搜 **Configure vJoy** 打开配置：
   - 勾选 **Device 1**
   - **6 根轴全勾**：X、Y、Z、Rx、Ry、Rz，范围保持 0–32767
   - **按钮数量至少 8**（默认可能是 0，那样襟翼和起落架就没有落脚点）
   - 点 **Apply**，再点 **Reset**（确认能写进去）
4. 打开「设置 → 蓝牙和其他设备 → 设备」，应该能看到一个 **vJoy Device**。

> 少勾一根轴不会报错，只会**静默失败**：那根轴永远不动。`vjoy_out.py` 会检查
> 每次写入的返回值，一旦发现写不进去，会在窗口里点名，并让手机端显示
> 「摇杆缺轴 · 查 Configure vJoy」。

### 会有什么副作用

安装后系统里会多一个游戏控制器。对 DCS 的影响很小——DCS 按设备名+GUID 记住绑定，
新设备只是多出一列，不会打乱已有的物理摇杆/油门绑定。

但如果你的物理摇杆是**按顺序号**被别的软件识别的（少数老工具会这样），编号可能变化。
真遇到这种情况，在设备管理器里禁用 vJoy 就能恢复。

## 三、三个页面

| 页面 | 用途 |
|---|---|
| **仪表** | 飞行数据（速度带、姿态仪、高度带、航向带） |
| **摇杆** | 操纵台：油门 / 杆位盘 / 襟翼 / 起落架 / 视角 / 解锁 |
| **校准** | 校零、握法、翻转、行程 / 死区 / 曲线 |

飞行页的版面按「离手多远」排：油门贴左边缘（左拇指），杆位盘居中（只显示、
不响应触摸），脚舵滑块在杆位盘正下方，视角区偏右（右拇指），动作按钮在底部中间。

杆位盘在飞行页**故意不可交互** —— 飞行中误触一个可交互区域，比少一个功能危险得多。
脚舵需要能一直压着，所以单独给了它一条实心滑块，而不是塞进盘里。

## 四、在 DCS 里绑轴

**先启动 DCS**（vJoy 必须在 DCS 启动前就存在，DCS 只在启动时枚举设备）。

1. `设置 → 操控 → 选中你的机型 → 轴命令`
2. 逐个绑定，点它右侧 **vJoy Device** 那一列的格子，然后**动对应的手机操作**
   （倾斜 / 拧 / 划油门条 / 按住视角区拖），DCS 会自己识别到轴：

   | DCS 轴命令 | vJoy 轴（列名里的 JOY_xxx） | 手机操作 |
   |---|---|---|
   | `Roll` | **JOY_X** | 左右倾斜 |
   | `Pitch` | **JOY_Y** | 前后倾斜 |
   | `Rudder` | **JOY_RZ** | 压脚舵滑块（或拧手机） |
   | `Throttle` | **JOY_Z** | 左侧竖条上/下划 |
   | `Absolute Camera Horizontal View` | **JOY_RX** | 视角区左右拖 |
   | `Absolute Camera Vertical View` | **JOY_RY** | 视角区上下拖 |

3. 点 **轴调整**，把这些轴的 **死区设为 0、曲率设为 0**

第 3 步很重要。死区和曲线已经在手机端做了（可以实时调），DCS 里再叠一层会让
手感变成两个曲线的乘积，中间会非常钝，而且两边都调不出想要的效果。

4. 襟翼和起落架是**按钮**，在 `操控` 里找到命令（`Flaps Up` / `Flaps Down` /
   `Landing Gear`），点 `vJoy Device` 那一列，然后按手机上的对应按钮：

   | 手机按钮 | vJoy 按钮 | DCS 里长这样 |
   |---|---|---|
   | 襟翼↑ 收起 | **Btn 1** | `JOY_BTN1` |
   | 襟翼↓ 放下 | **Btn 2** | `JOY_BTN2` |
   | 起落架 收放 | **Btn 3** | `JOY_BTN3` |

### 视角轴要认准「Absolute」

DCS 里有两套视角轴，**名字很像但性质完全不同**：

| 名字 | 性质 | 能不能绑摇杆 |
|---|---|---|
| `Camera Horizontal View`（带 mouse 后缀那组） | 鼠标**增量**轴 | **通常灰掉，绑不了** |
| `Absolute Camera Horizontal View` | 绝对角度轴 | ✅ 就绑这个 |

很多人卡在「视角轴是灰的、绑不上」，就是因为选错了那一项。
我们发的是绝对位置（推多少偏多少、松手回中），正好对应 `Absolute` 这一组。

> **绑视角时的一个坑**：DCS 是「动一下它自己认这根轴」。而视角摇杆如果按
> 「按到哪算到哪」的绝对定位，手指一按下两个轴会同时跳 —— 按得偏上一点，
> 它就把 `Horizontal View` 认成 `JOY_RY`。
> 现在视角摇杆已经改成**从按下点开始算**：按下瞬间恒为零，只有拖动才产生偏转，
> 所以不会再认错。万一已经绑错了，不必重绑 —— 打开校准页的
> **「视角 横纵互换」**就能救回来。

> 如果你的机型在轴命令里**根本没有** `Absolute Camera ...` 两项：
> 需要往机型的轴定义文件里补两行，例如
> `Mods\aircraft\<机型>\Input\<机型>\joystick\default.lua`，在 `axisCommands` 末尾加：
>
> ```lua
> {combos = {{key = ''}}, action = iCommandViewHorizontalAbs, name = _('Absolute Camera Horizontal View')},
> {combos = {{key = ''}}, action = iCommandViewVerticalAbs, name = _('Absolute Camera Vertical View')},
> ```
>
> 改完重启 DCS 就能绑了。注意游戏更新会覆盖，建议用 JSGME 之类的工具挂着。
> 不想折腾的话，视角继续用鼠标也完全能飞 —— 摇杆和油门不依赖它。

> 方向反了怎么办：先试手机端校准页的「左右 反转 / 前后 反转 / 脚舵 反转 / 油门 反转」，
> 那是最快的一层。也可以在 DCS 的轴调整里勾 Invert，但建议只在一处翻转，
> 否则以后排查会绕晕。

## 五、油门为什么特殊

油门是唯一一个**松手不该回零**的通道。这个区别贯穿了整条链路：

| 场景 | 杆 / 脚舵 / 视角 | 油门 |
|---|---|---|
| 未解锁 | 发 0 | **根本不发**（DCS 保持自己的油门） |
| 没碰过滑块 | — | **也不发**（避免一解锁就把油门拽到慢车） |
| 断线看门狗 | 回中 | **保持**（进近中断线时把油门拽回慢车会直接掉下去） |
| 点「上锁」 | 发 0 | 停止发送，停在原地 |

所以正确的用法是：**先把油门条划到位，再解锁**。

油门条的颜色表示状态：**灰** = 还没接管（飞机不受它影响），**琥珀** = 已接管但
未解锁，**绿** = 正在控制油门。数字一直显示，因为它是「碰一下会发出去多少」——
显示 `--` 的话，用户不知道第一次触摸会把油门带到哪里。

油门值会被记住：App 重启后滑块停在原处（灰色），所以第一次碰它不会从 0 重新
开始。但它**不会自动接管**——重启后仍要你主动碰一下才会重新控制油门。

油门的交互是**相对拖动**（划一下动一点），不是「点哪跳哪」。绝对定位下，
飞行中一根误触的手指就能把油门甩到满推力 —— 慢半拍换安全，值得。

## 六、调手感

### 配平（直升机必看）

杆位盘正下方有个 **「配平」** 按钮：

| 操作 | 效果 |
|---|---|
| **单击** | 把当前杆位记成配平量，之后**松手也停在这儿** |
| **长按**（0.7 秒） | 清零，杆回到中立 |

按钮上会显示当前配平量，比如 `配平 +32%`；没配平时就是灰的「配平」。上限 ±70%。

**为什么需要它**

手机是「绝对位置」映射：手机放平 = 轴回 0 = 杆回中立。固定翼没问题（杆中位在设计上就是平飞配平点），但**直升机的中立周期变距不是平飞位**——悬停和巡航往往要一直顶着杆。真实直升机靠 force trim 把杆位锁住，松手停在那儿；我们没有力反馈杆，只能软件补一层。

所以在直升机上你会看到：手机放平 → 飞机后仰 → 必须一直前推。这时候**保持前推，点一下「配平」**，之后松手就等于一直前推。

**方向怎么看**：读数是加到输出上的偏移量，正负取决于你有没有开「反转」。不用记方向，按住杆到平飞、点一下配平就完事了；配错了再点一次重配。

**什么时候别用**：固定翼。它不按就一直是 0，理论上不影响，但如果你配过一次忘了清，起飞时会带着一个杆量。落地换机型前长按清一下。

**注意**：上锁（`ARM` 灭）时配平量仍然记着，解锁后会立刻生效。如果落地后不想带着它，长按清零。

### 参数

校准页的步进参数，改完立刻生效并持久化：

| 参数 | 默认 | 含义 | 怎么调 |
|---|---|---|---|
| **行程** | 22° | 杆打到满要倾斜多少度 | 太灵敏/容易过量就调大；转不动就调小 |
| **死区** | 2.5° | 中位附近多大范围算「没动」 | 手放上去杆就自己抖，就调大；中位黏滞就调小 |
| **曲线** | 0.35 | 0 = 线性，1 = 纯三次方 | 调大：中位更细腻、大杆量仍能到满。狗斗建议 0.4–0.6 |
| **拧舵行程** | 28° | 拧多少度算满舵（只影响拧手机，滑块不受影响） | 手腕拧不到那么远就调小 |
| **脚舵死区** | 4° | 拧手机时中位附近算没动 | 不拧也在偏就调大 |

开关：

- **横握 / 竖握** —— 决定三根分量各自对应哪个动作。横屏拿着手机就选横握；
  如果发现推左右变成推前后、或者拧手机变成横滚，就是这里选错了。
- **拧手机 开/关** —— 关掉就不采集拧动。滑块不受影响，所以想用纯滑块操纵
  脚舵可以直接关掉它。
- **左右/前后/脚舵/油门 反转** —— 方向反了先动这里。
- **视角 横纵互换 / 视角横 反转 / 视角纵 反转** —— 视角专用的三个开关。
  互换是给「DCS 把横轴认成了竖轴」准备的；两个反转是给上下/左右颠倒准备的。
  这三个都是发送前的最后一道变换，不影响其他通道。

杆位盘是调参时的眼睛：绿点就是当前杆位，网格是 ±25%，底部那条横槽是**脚舵**
（显示的是最终给飞机的偏航量，不管来自滑块还是拧动）。静止时绿点抖不抖 →
死区合不合适；横滚时脚舵小方块跟着动 → 握姿带出了多余偏航，把「拧舵行程」
调大或把「拧手机」关掉。

标定脚舵方向：解锁后压滑块右侧，飞机的机头应该往右偏。反了就把「脚舵 反转」
打开。

## 七、安全机制

手机当摇杆最大的风险不是延迟，是**它会在你不知情的时候继续输出**。
vJoy 是状态保持的：写进去一个杆位，即使写它的程序被杀掉，那个值也会一直留着。

所以做了四层，互相独立：

| 层 | 触发条件 | 动作 |
|---|---|---|
| **解锁** | 默认是锁的 | 只发 0，油门不发 |
| **超限归零** | 倾角超过 `max(55°, 行程×1.8)` | 该帧输出 **0**（不是钳到满舵） |
| **超限上锁** | 上面这个状态持续 1.2 s | 上锁，界面变红并说明原因 |
| **断链上锁** | 连续 3 帧发送失败 | 立刻发 0 并上锁 |
| **PC 看门狗** | 500 ms 没收到新操纵量 | 回中五个轴、释放全部按钮、**不动油门** |
| **退出归零** | Ctrl+C、关窗口、注销 | 先 `ResetVJD` 再释放设备 |

关于「超限归零」：曲线对超出量程的输入会 clamp 到 1.0，也就是**满舵**。
用户只是把手机翻过来看一眼，飞机就会突然满舵横滚 —— 钳位是数学上正确、
操作上危险的行为，所以超限时直接输出零。

关于「发送失败要上锁而不是重试」：链路恢复的瞬间，如果飞机还停在断线前那个舵量上，
会突然满杆回弹，比失控更危险。上锁以后必须人工再点一次，麻烦，但不会让人措手不及。

**救急**：`python tools/vjoy_out.py --reset` 强制回中并释放设备。

## 八、排障

先看手机摇杆页那两行字，它们能直接定位断在哪一跳：

| 现象 | 断点 | 处理 |
|---|---|---|
| 「未设置服务器地址」 | 没配地址 | 点右上「设置」，填 `http://127.0.0.1:8080` |
| 「虚拟摇杆未运行 · 杆不会动」 | `vjoy_out.py` 没跑 | 看启动器窗口里 `[vjoy]` 那几行的报错 |
| 「摇杆缺轴 · 查 Configure vJoy」 | 驱动在，但轴/按钮没启用 | 打开 Configure vJoy 勾上 6 轴 + 8 按钮 |
| 「就绪」但**只有某几根轴不动** | 该轴没启用 | 同上 |
| 「就绪」但飞机完全不动 | DCS 没绑轴，或 vJoy 在 DCS 启动后才装 | 重启 DCS，重新绑轴（第四节） |
| 杆量方向全反 | 三根轴都没翻转 | 校准页逐个试「反转」 |
| 推左右变成推前后 | 握法 | 切「横握 / 竖握」 |
| 横滚时飞机带偏航 | 拧手机被带出来了 | 关掉「拧手机」，改用滑块 |
| 脚舵滑块压了没反应 | DCS 没绑 Rudder，或 vJoy 没启用 Rz 轴 | 见第四节 / 第二节 |
| 脚舵方向反了 | — | 打开「脚舵 反转」 |
| 飞机自己往一边偏 | 没校零，或校零后换了握姿 | 重新「校零」；静止时杆位盘绿点应在中心 |
| 解锁后又自己锁上 | 倾角超限 / 链路断 | 看解锁键下面那行琥珀色提示，它写着原因 |

如果提示「发送失败，已自动上锁」：那是网络真的断了（连续 3 帧，单次抖动不会触发）。
检查 USB 线、`adb reverse`、以及启动器窗口里 `[watch]` 的心跳。

## 九、已知限制

- **视角轴不一定可用**。部分机型/版本在轴命令里没有 View Horizontal/Vertical。
  没有的话，DCS 只能用鼠标看四周（或者外接头部追踪），手机这边帮不上。
- **绝对位置映射，不是速度映射**。手停在某个角度 = 杆停在某个位置。
  这和真实驾驶杆一致，但长时间保持大杆量会比较累。
- **会漂移**。`TYPE_GAME_ROTATION_VECTOR` 不融合磁力计（避免室内磁干扰），
  代价是零漂，大约几分钟几度。觉得杆位跑偏了就再点一次「校零」。
- **拧手机做脚舵需要练习**。横滚时手腕会带出一点偏航，这是物理耦合，
  软件只能淡化（死区 + 拧舵行程）不能消除。不想练就关掉它，用滑块。
- **后台自动上锁**。App 一进后台就停手，这是刻意的——系统会限流后台传感器，
  继续挂着解锁状态会保持住最后一帧的舵量。
- **只支持 3 个按钮**。vJoy 支持 128 个，通道也留了 16 位，加按钮只需要
  在 `YokeBtn` 里加常量、在飞行页加一个 `HoldButton`。
- **脚舵滑块没有回中弹簧的手感**。真实脚舵是踩多少有多少、松脚回中；
  滑块是「压哪算哪、抬手回中」，落地修正时需要一直按着。想要持续偏航
  可以先把机头偏过来再松手（松手 = 回中），而不是一直压着。
