# 多端 DCS 外设 · 测试方案

> 版本 0.1 · 2026-11-10
> 配合 `docs/ROADMAP.md` 使用。每个阶段结束时，对照 §8 的准出矩阵验收。

---

## 1. 测试原则

五条，破了任何一条，测试体系就会退化成摆设。

1. **CI 里永不依赖 DCS。** 所有涉及 DCS 的路径，必须有 mock 等价物或录制回放。否则 CI 只在你开着游戏的那台机器上绿。
2. **退出准则先写成测试，再写实现。** 每个阶段开工第一件事是把该阶段的测试用例补齐（可以全部红着），然后才动代码。
3. **延迟是要测的指标，不是感觉。** 任何「好像有点卡」的反馈，必须落到 §3 的指标表上。
4. **安全测试要主动攻击，不能只看配置。** 「我开了 TLS」不等于安全，要真的用 `openssl`、`arpspoof`、改 pin 去打。
5. **降级路径必须被测。** 断网、丢包、证书不匹配、DCS 退出、显卡不支持硬编——每一条降级都要有对应用例，且必须产生可见提示，不许静默。

## 5. 关键测量方法

### 5.1 输入延迟

三条路，用在不同场合。

**方法 A · 帧标记法（最准，用于里程碑验收）**
PC 屏幕上叠一个随帧号变化的色块，Pixel 上同帧显示同一色块。用 240 fps 慢动作同时拍下两块屏，读两帧差。
- 优点：测量的是真实用户感知延迟，包含显示刷新
- 缺点：手工、耗时，只做里程碑

**方法 B · 回环法（用于日常回归）**
客户端发 `Cmd(seq)`，服务端收到后立刻回 `Ack(seq)`。客户端测 RTT。
- 优点：可全自动化，反映网络下界
- 缺点：不含 DCS 处理与渲染时间，是下界不是全貌

**方法 C · 打点法（用于定位瓶颈）**
在 `Export.lua` 里给座舱参数变化打上 DCS 帧时间戳，客户端收到回传时记录本地时间，两者相减。
- 优点：能拆出「网络」与「游戏帧」两段
- 缺点：依赖 DCS 时间戳可信

**实务组合**：日常跑 B（每 PR），里程碑跑 A（每阶段一次），出问题时用 C 拆解。

### 5.2 视频延迟

**时钟同框法**：PC 屏幕全屏跑一个毫秒计时器，Pixel 上显示同一路视频。用一台 240 fps 相机同时拍下两块屏，读两个数字之差。重复 20 次取 p95。

比帧标记法更直接，因为视频延迟最容易在这一步翻车。

### 5.3 中间人攻击模拟

| 方式 | 门槛 | 覆盖 |
|---|---|---|
| 改客户端 pin 后连接（负向验证） | 低，自动化 | 只证明「pin 生效了」 |
| 局域网内 `arpspoof` + 伪造服务端 | 中，需第二台设备 | 逼近真实攻击 |
| 伪造同一 SSID 的 AP | 高 | 最真实，里程碑做一次 |

第三种需要一张支持 AP 模式的网卡（Linux + hostapd）。做一次即可，用于验证「假 AP」场景下客户端不会盲目连接。

### 6.1 目录结构

```
tests/
├── fixtures/
│   ├── clickabledata/       # 各机型 lua 样本（脱敏、可入库）
│   ├── proto-binary/        # 手工构造的畸形帧
│   ├── recording/           # 真机遥测录制，jsonl
│   └── profiles/            # 校验用 Profile（含故意非法的）
├── unit/                    # cargo test / JUnit
├── integration/             # 跨组件
├── e2e/                     # 真机脚本（adb + uiautomator）
├── netem/                   # 网络损伤脚本
└── perf/                    # 基准与回归基线
```

### 6.2 录制回放（重要）

**目的**：把「在真 DCS 里飞的一段」变成可重复、可入库、可 CI 的输入。

格式：`jsonl`，每行一条带时间戳的快照或指令：

```json
{"t": 0, "type": "snapshot", "alt": 1520.3, "ias": 245.1, "pitch": -0.02}
{"t": 16, "type": "snapshot", "alt": 1520.9, "ias": 245.4, "pitch": -0.03}
{"t": 120, "type": "cmd", "id": "MASTER_ARM_SW", "v": 1}
```

回放器按原时间轴重放，时间偏差 < 20 ms。**所有 UI 回归、性能基线、长稳测试都跑在录制上**，而不是现场飞。

录制清单（至少要这几段）：
- 冷启动到滑行（慢变化，测插值）
- 起飞爬升（快速变化，测刻度滚动）
- 剧烈机动 + 过载（测指针平滑与震动触发）
- 开关密集操作（测指令吞吐）
- 断开重连（测状态重同步）

## 9. 缺陷分级与准出

| 级别 | 定义 | 例子 | 准出要求 |
|---|---|---|---|
| **P0 阻断** | 连不上、指令错误、安全缺陷、数据丢失 | NaN 透传导致 DCS 崩溃；证书校验可绕过 | 必须 0 |
| **P1 严重** | 功能不可用或指标严重超标 | 延迟 p95 > 200 ms；看门狗不触发；断线后幽灵按下 | 必须 0 |
| **P2 一般** | 功能可用但体验受损 | 某 widget 在 360dp 下截断；重连弹窗不消失 | ≤ 3，且有明确排期 |
| **P3 轻微** | 文案、动效、非关键视觉 | 单位标签大小写不一致 | 不限 |

**延迟与安全相关的缺陷，一律不得降级处理。**
