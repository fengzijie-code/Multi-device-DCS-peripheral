# iPad 输入端（`/yoke`）

> 2026-11-18 · 用 iPad Pro 11"(M4) 替代 Pixel 当杆/油门/脚舵/按钮
> 页面：`tools/yoke.html`　路由：`http://<PC>:8080/yoke`

手机（Pixel 6a）当摇杆的问题是**太小**：杆位区、油门条、发射键挤在 6.1 寸里，
盲操基本靠记位置。11 寸 iPad 有 1210×834 的可用面积，同一套通道能摆得很开。

---

## 一、这不是浏览器标签页

`/yoke` 是给 **「添加到主屏幕」** 用的。做法：

1. PC 上照旧双击 `tools\start-usb.bat`
2. iPad Safari 打开 `http://<PC的IP>:8080/yoke`
3. 分享 → **添加到主屏幕** → 命名为「DCS 杆」
4. **从桌面那个图标启动**（不是从 Safari 里的书签）

这样启动的是 iPadOS 的 standalone 窗口：没有地址栏、没有工具栏、没有下拉刷新，
全屏铺满，和 app 的观感一致。`apple-mobile-web-app-capable` 那几个 meta 就是干这个的。

### 为什么不打包成真 app

用户手上**没有 Mac**。iOS 应用必须有 Xcode 出的 IPA 才能装，所以只剩三条路：

| 方案 | 代价 |
|---|---|
| 云构建（GitHub Actions macOS）+ AltStore/Sideloadly 自签 | 免费证书 **7 天过期**，PC 上跑 AltServer 才能自动续签 |
| 同上 + 付费开发者账号 | $99/年 |
| Pythonista 之类第三方 App 写界面 | 受限于那个 App 活着、性能受限 |

而 standalone 窗口已经把「浏览器不舒服」的 90% 解决了。**只有三件事真 app 才有**：

- 底部那条 home indicator 去不掉
- 触摸事件 60Hz 上限（ProMotion 的 120Hz 用不上；DCS 本身 60Hz，实际影响小）
- 内存紧张时 Safari 可能重载页面（`visibilitychange` 里已做兜底回中）

先按 standalone 飞一段，真觉得不够再谈云构建。

## 二、版面 ↔ 通道

横屏 1210×834（竖屏能用但挤，页面会提示「建议横屏」）。

| 位置 | 控件 | 通道 | vJoy | 类型 |
|---|---|---|---|---|
| 最左竖条 | 油门 | `t` | Z | **保持**（松手停在原地） |
| 左上（两个大片） | 左舵 / 右舵 | `r` = ∓1 | Rz | 按住 |
| 左下 3×2 | 襟翼收 / 襟翼放 / 起落架 / 减速板开 / 减速板收 / 轮刹 | `b` bit 0,1,2,12,13,14 | BTN1/2/3/13/14/15 | 按下（轮刹按住） |
| 中间大圆盘 | 杆量 | `x` `y` | X / Y | 回中 |
| 右上 2×2 | 机炮 / 投放 / 干扰弹 / 武器切换 | bit 11,6,10,3 | BTN12/7/11/4 | 按下 |
| 右侧 | 雷达锁定 | bit 5 | BTN6 | 按住 |
| 右下菱形 | TDC 上/下/左/右 | bit 7,8,9,4 | BTN8/9/10/5 | 按住 |

编号含义见 [`BINDING.md`](BINDING.md) —— 代码从 0 数、DCS 显示从 1 数，差一位。

## 三、协议：还是原来那条

50Hz `POST /input`，字段与手机端**完全一致**，所以 `beacon.py` / `vjoy_out.py` 一行没改：

```json
{"x":0.42,"y":-0.13,"r":0.0,"t":0.75,"b":2048}
```

两个必须守住的语义：

- **`t` 在用户第一次碰油门之前不许发。** beacon 把「缺失的 t」解释成「这次别动油门」，
  发 `0` 会把飞机直接拽到慢车 —— 手机端当初就是为这个专门做过处理，这里照抄。
- **`b` 是位图**，多指同时按住同一个键时按指针计数，最后一个手指抬起才清位。

## 四、手感

**杆盘是「浮动相对位移」**：手指按下去的位置成为新的中心（画一个环），拖动产生偏移，
推过行程边缘时中心跟着走 —— 这样从哪儿按都推得到满行程，不会出现「按在边上往那边推不动」。
松手立即 `x=y=0`（回中）。

- 行程 = `min(圆盘宽,高) × 0.34`，输出夹在 ±1
- **没有死区、没有曲线**：曲线留给 DCS 里那 15–25 的响应曲线调，两边都加会互相干扰
- 上推 = `y` 正。方向反了别改页面，用顶栏的 `X 反` / `Y 反`（存 localStorage），
  或者 DCS 里点 Invert

**油门**是绝对位置：点在哪个高度就是多少（顶部 100%）。保持型，松手不掉。
没碰过时显示 `未接管`（琥珀色），此时不发 `t`。

**脚舵**是两个「按住」大片，不占杆盘。松手回 0。

## 五、已知限制

| 限制 | 说明 |
|---|---|
| 没有配平 | 手机端那个配平是直升机用的开关（固定翼默认关），iPad 这版没做 |
| 没有体感倾斜 | 页面上拿不到可靠的 DeviceMotion（要用户手势授权、http 下能否拿到看 iOS 版本），而且 444g 的平板拿手上转不是个好交互 |
| 竖屏只是凑合 | 按钮会变两列，能按但不舒服 |
| 断线就回中 | `vjoy_out.py` 的 531ms 看门狗兜底，页面自己 3 次失败会显示 `断开 · 重试中` |

切走/锁屏时页面会**主动把所有输入清零**（`visibilitychange` + `blur` + `pagehide`），
避免恢复时杆量还卡在半路。

## 六、验收

```bat
python tools\beacon.py --port 8096 --ipv4-only
python tools\check-yoke.py 8096
```

`tools/check-yoke.py` 用 playwright + 系统 Chrome，在 1194×834 的 iPad 横屏视口里**真的发触摸事件**
（CDP `Input.dispatchTouchEvent`），然后回头查 `/input` 收到了什么 —— 18 项断言：

- 杆盘是正方形、≥400px、推过头仍夹在 1.0、松手回中
- 未碰油门时 `/input` 里**没有** `t` 字段
- 油门 1/4 处 ≈ 0.75，松手保持
- 机炮按下 = bit11，松开清零；左舵 = `r` 负
- 无 console 报错、无元素溢出视口
