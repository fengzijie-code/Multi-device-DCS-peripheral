# iPad 输入端（`/yoke`）

> 2026-11-18 · 用 iPad Pro 11"(M4) 替代 Pixel 当杆/油门/脚舵/按钮
> 页面：`tools/yoke.html`
> 入口：`https://<PC>:8443/yoke`（要体感就用这个）· `http://<PC>:8080/yoke`（备用，无体感）
> 8443 同时吃得下明文和 TLS，所以两种写法都能打开页面，左上角会显示当前是哪个。

手机（Pixel 6a）当摇杆的问题是**太小**：杆位区、油门条、发射键挤在 6.1 寸里，
盲操基本靠记位置。11 寸 iPad 有 1210×834 的可用面积，同一套通道能摆得很开。

---

## 一、这不是浏览器标签页

`/yoke` 是给 **「添加到主屏幕」** 用的。做法：

1. PC 上双击 **`tools\start-ipad.bat`**（不等手机、不建 adb 隧道，只起 beacon + vjoy；
   证书存在时会自动多开一个 8443 的 HTTPS）
2. iPad Safari 打开 `http://<PC的IP>:8080/yoke`（要体感就用 `https://<PC的IP>:8443/yoke`）
3. 分享 → **添加到主屏幕** → 命名为「DCS 杆」
4. **从桌面那个图标启动**（不是从 Safari 里的书签）

这样启动的是 iPadOS 的 standalone 窗口：没有地址栏、没有工具栏、没有下拉刷新，
全屏铺满，和 app 的观感一致。`apple-mobile-web-app-capable` 那几个 meta 就是干这个的。

### 一键启动脚本做了什么

`tools\start-ipad.bat` 本身几乎不干活：找到 python、把 `%*` 原样递给
`tools\start.py`、退出码非 0 时 `pause` 让窗口别闪就没。**所有中文提示都在
`start.py` 里**，因为 `.bat` 里的中文会被控制台代码页搅烂，然后后面每一行都被
当成命令解析 —— 这是「窗口一闪就没了」最经典的成因。`.bat` 保持纯 ASCII。

`start.py` 在起服务之前查四件事，因为这四件在 iPad 上的表现**一模一样**，
都是「打不开 / 已丢失网络连接」，不查就只能对着 iPad 猜：

| 查什么 | 不查会怎样 | 自己怎么修 |
|---|---|---|
| 证书在不在、剩几天 | Safari 报「不是私密连接」 | 自动调 `make-cert.py` 重签 leaf，根 CA 不动 |
| 证书 SAN 里有没有**当前这个 IP** | 换热点/换网线后必炸 | 同上，重签后 iPad **不用重装描述文件** |
| 8080 / 8443 / 5011 有没有被上次的窗口占着 | 服务起不来，页面打不开 | 印出占用者 `python.exe (PID 1234)` 和现成的 `taskkill` 命令 |
| 防火墙规则 `DCS Peripheral Bridge` 在不在 | iPad 连不上，八成就卡在这 | 提示跑一次 `open-firewall.bat`，或 `start.py --firewall` 自动提权 |

服务起来之后它会去问自己的 `/info`，把**真实在听的那个 IP** 印成可直接点的地址
（不是从 `ipconfig` 里猜，那会混进网关、虚拟网卡、169.254 自分配地址），
再顺手自检 `http 200 · https 200`。

> **端口判据为什么用 `netstat` 的 LISTENING 行，而不是试探性 bind。**
> Windows 的 `SO_REUSEADDR` 语义和 Unix 相反：端口正被别人 `listen` 着，
> 加了 `SO_REUSEADDR` 的 `bind` **照样成功**（这正是 Windows 上端口劫持能成立的
> 根因）。实测 `bind ok` 但端口确实被占，于是预检会印出假的「都空闲」，
> 而真正的失败推迟到 beacon 的 `listen` 那一步，表现成「窗口一闪」。
> 所以 TCP 走 `netstat` 判 LISTENING，UDP 没有 LISTENING 状态、只能试绑
> （UDP 不加 `SO_REUSEADDR`，绑失败就是真占用）。

停止：窗口里 `Ctrl+C`。批处理问 `Terminate batch job (Y/N)?` 时答 **N** 才能看到
最后几行；答 Y 也行，`run-all` 在 `KeyboardInterrupt` 里已经把子进程逐个停掉、
**vJoy 先回中**再退，两条路都会回中。

### 两个会让人以为「功能没做」的坑

**① 改完 `beacon.py` 必须重启进程。** 它是常驻服务，进程里跑的是启动那一刻的代码。
症状很好认：新路由一直 404，而且 404 页只列着旧的三个入口。
`start-ipad.bat` / `start-usb.bat` 的窗口关掉重开即可（监管进程会连带重启子服务）。

**② 手机上那个 App 必须关掉。** 它还活着的话会继续以 50Hz 往 `/input` 灌数据
（经 adb reverse 隧道，看起来是 `127.0.0.1`），和 iPad 抢同一个输入源 ——
表现是杆量一顿一顿地回中。关掉：

```bat
adb shell am force-stop com.fengzijie.dcsperipheral
```

`start-ipad.bat` 不建隧道，但**已经存在的** `adb reverse` 不会自动拆，所以还是要手动关 app。

### 为什么不打包成真 app

用户手上**没有 Mac**。iOS 应用必须有 Xcode 出的 IPA 才能装，所以只剩三条路：

| 方案 | 代价 |
|---|---|
| 云构建（GitHub Actions macOS）+ AltStore/Sideloadly 自签 | 免费证书 **7 天过期**，PC 上跑 AltServer 才能自动续签 |
| 同上 + 付费开发者账号 | $99/年 |
| Pythonista 之类第三方 App 写界面 | 受限于那个 App 活着、性能受限 |

而 standalone 窗口已经把「浏览器不舒服」的 90% 解决了。**只有三件事真 app 才有**：

- 底部那条 home indicator 去不掉
- 触摸事件 60Hz 上限（ProMotion 的 120Hz 用不上；DCS 本身 60Hz，实际影响小）
- 内存紧张时 Safari 可能重载页面（`visibilitychange` 里已做兜底回中）

先按 standalone 飞一段，真觉得不够再谈云构建。

## 二、版面 ↔ 通道

横屏 1194×834。**只做横屏**，竖排不管（这套版式在竖屏下没有意义）。

### 美术：玻璃 HUD，不是仪表盘

整页只有一条原则：**不画面板**。没有卡片底色、没有边框盒子、没有实心顶栏，
只有 1px 细描边、圆、小字距的浅色字，和极少量强调色（洋红 / 红 / 琥珀）。
UI 是"浮"在背景上的，不是"贴"上去的。

这条约束是硬的：所有控件都必须能在**没有底板**的情况下读清楚，
所以禁止用"加深底色 / 加粗边框"来补救可读性 —— 那就退回到卡片了。
需要强调时只有三种手段：描边变亮、加一层极淡的发光、缩进一点（按下）。

状态色用法也固定下来了，别乱加：

| 颜色 | 只用于 |
|---|---|
| 青 `#6fe3cb` | 已连接 / 油门当前值 / 已解锁 |
| 洋红 `#e33f92` | 上锁 / 油量那条细线 |
| 蓝 `#63c8ff` | 右舵 |
| 琥珀 `#ffb454` | 未接管 / 左舵 / 载荷告警 |
| 红 `#ff4a4a` | 开火 / 投放 / 过载 |

### 四页

照 Pixel 的 `pfd / yoke / combat / calib` 搬过来，页签在右上角（细圆 + 左置标签）：
**仪表 / 起降 / 战斗 / 校准**。

| 页 | 左 | 右 |
|---|---|---|
| 起降 | 油门竖条 | 六个圆形起降键（脚舵在右下角，两页都有） |
| 战斗 | 同上 | 四个武器圆 + 雷达锁定 + TDC 四向圆阵 |
| 仪表 | 一整屏大表（460px 姿态球 + 10 个数字框） | — |
| 校准 | 手感参数 + 体感校准（宽屏分两栏，一屏放下） | — |

**杆盘不跟页翻**，常驻中间偏左；起降和战斗都只换右列内容。
两列宽度都是写死的，换页时杆盘坐标不变（验收里有硬断言 `切页后杆盘不挪位`）。
要是让内容自己撑开会话，正在推杆时切页杆心会跳一下，杆量会甩。

杆盘外侧那圈 24 道刻度是用 `repeating-conic-gradient` + 环形遮罩画的，
不是 24 个元素 —— 别为了"好维护"改成 DOM，那会在拖杆时拖着 24 个节点重排。

| 位置 | 控件 | 通道 | vJoy | 类型 |
|---|---|---|---|---|
| 左·竖条 | 油门 | `t` | Z | **保持**（松手停在原地），发送值默认反转（`invT` 默认开），屏显不反转 |
| 右下角横条 | 脚舵（比例，松手回中） | `r` ∈ [-1,1] | Rz | 回中 |
| 中 | 杆盘 = 体感输入指示器（**纯体感，不吃触摸**）：绿点 = 当前体感杆位，贴 `.lim` 圈 = 满杆 | `x` `y` | X / Y | 回中 |
| 起降·右列 | 襟翼收 / 襟翼放 / 起落架 / 减速板开 / 减速板收 / 轮刹 | `b` bit 0,1,2,12,13,14 | BTN1/2/3/13/14/15 | 按下（轮刹按住） |
| 战斗·右列 | 机炮 / 投放 / 武器切换 / 干扰弹 | bit 11,6,3,10 | BTN12/7/4/11 | 按下 |
| 战斗·右列 | 雷达锁定 | bit 5 | BTN6 | 按住 |
| 战斗·右列 | TDC 上/下/左/右 | bit 7,8,9,4 | BTN8/9/10/5 | 按住 |

圆形按钮上**不写字**，标签放在圆的左边（右对齐、两行：主名 + BTN 号）——
圈里塞字会立刻变成"按钮控件"，不写字才像座舱。

编号含义见 [`BINDING.md`](BINDING.md) —— 代码从 0 数、DCS 显示从 1 数，差一位。

### 四角与底边

| 位置 | 东西 | 说明 |
|---|---|---|
| 左上 | `●` + `已连接` + `https`/`http` | 后者是**服务端**判定的（`POST /input` 回包的 `sec`），主屏窗口没有地址栏，靠它分辨入口 |
| 左边第二行 | 配平 / 清配平 / 体感 / 校零 / 手感 | 安全与手感，见第四节；`手感` 直接跳到校准页 |
| 左下 | **解锁 / 已解锁**（100px 大圆） | 见下面那一段。原来它是顶上一颗 chip，拇指够不着 |
| 右上 | 四个页签圆 | 当前页存在 `localStorage`，刷新后还停在那一页 |
| 底部 | 姿态球 + `IAS ALT VS G HDG FUEL` + `RTT/收/抖动/vJoy` | 1Hz 拉 `/state`，纯显示、`pointer-events:none`，不跟杆盘抢触摸 |
| 底部中 | 一行琥珀色提示 | 体感开关、校零、自动上锁这类一次性消息，6 秒消失 |
| 顶部留白 | 最上面一行从 `y=38px` 起 | 主屏模式下 iOS 状态栏（时间 / 电量）会盖住页面顶边，顶上那一排必须整体让开；验收里有 `顶部留出让开状态栏` 一条盯着 |

**解锁键为什么单独拿出来放大。** 它是全页唯一"决定要不要往飞机发东西"的开关，
却原本是顶上一颗 11.5px 的 chip —— 实飞时右手在杆上、左手在油门条上，
没有一个指头会跑到左上角去点那么小的东西。现在它单独待在左下角：
100px 的圆、`left:22 / bottom:56`，和右下角的脚舵同一个水平线，拇指落下去就够到。
圆里两行字：大的一行是**动作**（`解锁` / `已解锁`），小的一行是**状态**
（`不发操纵量` / `正在发操纵量`），洋红 = 上锁、青 = 已解锁。

它挂在 `#deck` 里，所以只活在**起降 / 战斗**两页 —— 仪表页和校准页上没有任何操纵面，
那儿不需要它，也就不会去压 `#pfdSrc` 和校准页正文。油门竖条的高度同时改成
`min(500px, calc(100dvh - 330px))`：10.9 吋那种 768 高的屏上，固定 500px 会一路压到
解锁圆上，短屏得自己缩（834 高时仍是 500，验收里 `解锁键不压油门杆` 盯着这条）。

脚舵放在右下角而不是左侧：左上手边只留油门，右手管杆盘 + 按键 + 脚舵，
和真机的手位一致；放在左下时它会横穿杆盘的下圆弧，视觉上也打架。
（解锁键能去左下，是因为它只占 100px 见方的角落，正好落在油门竖条收尾之后的空档里。）

底部读数条只在 `DCS 遥测活着` 时显示数值，否则全是 `--`（宁可显示没数据，也不显示上一秒的旧数）。
单位按飞行习惯换算：米/秒 → 节、米 → 英尺、米/秒 → 英尺每分钟。油量按量级判断：
`≤1` 当比例显示 `%`，否则当公斤显示 `kg`。

仪表页是同一份数据的放大版，多给四个数：`AGL / MACH / AOA / RPM`。姿态球按
「相对 26px 那颗放大几倍」换算像素/度，所以大小变了姿态不会失真。

## 三、协议：还是原来那条

50Hz `POST /input`，字段与手机端**完全一致**，所以 `beacon.py` / `vjoy_out.py` 一行没改：

```json
{"x":0.42,"y":-0.13,"r":0.0,"t":0.75,"b":2048}
```

三个必须守住的语义：

- **`t` 在用户第一次碰油门之前不许发。** beacon 把「缺失的 t」解释成「这次别动油门」，
  发 `0` 会把飞机直接拽到慢车 —— 手机端当初就是为这个专门做过处理，这里照抄。
- **`b` 是位图**，多指同时按住同一个键时按指针计数，最后一个手指抬起才清位。
- **上锁时一个字段都不发操纵量**，且 `t` 直接省掉（见第四节）。

## 四、手感

### 安全三件事（照 Pixel 端搬的）

这一层比功能重要，因为它管的都是「会摔机」的那种意外：

1. **默认上锁。** 页面加载、断线重连、连续 3 帧发不出去，都自动上锁；
   上锁时只发全零，且**省掉 `t`**。网络恢复的瞬间把断线前的杆量重放一遍，
   是这类控制器最容易摔机的一种意外。上锁期间屏幕中央有一条提示，点**左下角那颗大圆**「解锁」才开始发。
2. **按钮最短脉冲 120ms。** DCS 在每个模拟帧采样一次按钮状态，触摸屏上一次快速点按
   可能只有 20ms —— 落在两次采样之间这一下就丢了，现象是「按了没反应，得多按几下」。
   按下时长不足 120ms 的，页面替用户按满。
3. **姿态异常兜底。** 只有相对校零点翻过 180°（物理上不可能的姿态）持续 1.2 秒才上锁。
   正常拉过载时 tilt 到 90°+ 是合法的满杆输入，不能当成掉手机 —— Pixel 端早前用 55°
   阈值，大过载机动会把人直接踢下来，这里已经改正。

### 杆盘（纯体感，无触摸）

**2026-11-20 起杆盘不再吃任何触摸**：杆量只来自体感（陀螺仪），盘面降级成纯输入
指示器 —— 绿点 = 当前体感杆位，贴到内圈（`.lim`，= 盘面半径 × 0.335）就是满杆。
触摸环和浮动锚点已整个撤掉。油门 / 脚舵 / 按钮仍是触摸，只有杆这条轴是体感专属。

- 输出夹在 ±1；体感没开时绿点不显示、杆量为 0
- 上推（拉杆）= `y` 正。方向反了别改页面，在「校准」页里翻 `X` / `Y`（存 localStorage），
  或者 DCS 里点 Invert。

### 体感曲线（在校准页里调）

默认值取自 Pixel 端 `YokeSettings`，是实飞调出来的那一组：

| 参数 | 默认 | 作用 |
|---|---|---|
| 死区 | 2.5° | 吃掉手持微抖，不给就会一直轻颤 |
| 满行程 | 22° | 倾斜多少度算满杆；越小越灵敏也越累 |
| 曲线 | 0.35 | `(1−e)·v + e·v³`，端点仍是 0/1，中间被压细 |

死区之后要**重新归一**（除以 `range−deadband` 而不是 `range`），否则刚出死区就到 12%
杆量，中位修正时有个跳变 —— 这种小跳变特别难受。

### 配平（force trim）

杆量只来自体感，「握平」不一定是平飞/悬停位 —— 直升机的中立周期变距**不是**平飞位，
悬停要一直顶着杆。真机靠 force trim 把杆位锁住，我们没有力反馈杆，只能在软件里补这一层：

- 上限 **±0.7**（满杆配平等于一起飞就压到底，不给到 1.0）
- 取「当前实际输出」当新偏移（已含旧偏移），所以连按是继续微调，不会翻倍
- 只在飞直升机时有用，飞固定翼可以在校准页里关掉 —— **关掉会同时清零偏移**，
  只藏不清是最坏的一种：切回固定翼时偏移还在，屏幕上却已经不显示它了

**油门**是绝对位置：点在哪个高度就是多少（顶部 100%）。保持型，松手不掉。
没碰过时显示 `未接管`（琥珀色），此时不发 `t`。

油门**默认反转**（校准页 `invT` 默认开）：DCS 那边油门轴方向相反，iPad 这头发
`1 − 手指位置` 去补。**反转只作用于发送值，永远不碰显示层** —— 屏上的油门条、
旋钮、百分比始终跟着手走，上推就是加油门。以前把反转完的值直接拿去画，
才会出现「手往上、屏上油门往下」的鬼画面（2026-11-20 修）。

**脚舵**是两个「按住」大片，不占杆盘。松手回 0。

## 五、体感（陀螺仪）

能做，但 iOS 有一道硬门槛，不是代码问题。

### 为什么必须 HTTPS

iOS 13 起，**传感器（方向 / 运动）只在安全上下文里可用**。WebKit 工程师在
[webkit.org/b/203287](https://webkit.org/b/203287#c5) 的原话：

> "I think also changed behavior in iOS 13 to require a secure context
> (file protocol, https or loopback), no HTTP."

也就是说 `http://192.168.137.1:8080/yoke` 上点「体感」永远不会来数据。
Chrome 更直接：非安全上下文里 `DeviceOrientationEvent` 整个从 `window` 上摘掉。

所以点「体感」时如果不在安全上下文里，页面会弹出**整屏引导**（不是闪一下就消失的提示）：
里面直接给出这台机器该用的 https 地址、一个「复制」按钮、一个「下载根证书」按钮，
和四步安装说明。照着做一遍就行，不用回来翻这份文档。

### 装一次根证书（之后就不用管了）

局域网 IP 拿不到公信证书，所以走本地 CA。PC 上先生成一次：

```bat
python tools\make-cert.py                      :: 生成 CA + 服务端证书 + 描述文件
python tools\make-cert.py --ip 192.168.50.1    :: 换网段时把新 IP 追加进去再签
```

`start-ipad.bat` 发现 `tools/certs/` 里有证书就会自动带上 HTTPS（默认 8443）。之后在 iPad 上：

1. 打开 `http://<PC的IP>:8080/yoke`，点「体感」→ 弹出引导页
2. 点页面上的**下载根证书**（就是 `http://<PC的IP>:8080/ca.mobileconfig`，
   Content-Type 为 `application/x-apple-aspen-config`，Safari 会认出来这是描述文件，
   不需要 AirDrop 也不需要发邮件）
3. 设置 → 通用 → VPN 与设备管理 → 已下载的描述文件 → 安装（提示「未签名」是正常的）
4. 设置 → 通用 → 关于本机 → 拉到最底 **证书信任设置** → 打开「DCS Peripheral Local CA」
5. 回 Safari 打开引导页给出的 `https://<PC的IP>:8443/yoke`，地址栏不再报警告

同一个文件有四个别名，给不同客户端兜底：`/ca.mobileconfig`、`/ca-mobileconfig`、
`/profile.mobileconfig`、`/ca`。

第 4 步最容易漏 —— 只安装不信任，证书依旧是「不受信任」，传感器照样被拦。
`tools/certs/` 已 gitignore，私钥不会进仓库；换了电脑或在仓库外重装要先跑一次 `make-cert.py`。

> **为什么非要装证书，而不是点「继续访问」**：普通标签页里自签警告能点
> 「显示详细信息 → 访问此网站」绕过去，体感也照样有数据（安全上下文看的是 scheme，
> 不看证书是否可信）。但「添加到主屏幕」的 standalone 窗口没有这个按钮，页面会直接白屏。
> 想长期用主屏图标，就必须让证书真的被信任。

> **端口不是写死的**：引导页会问 `/info` 要 `https_port` 的真实值，所以 `--tls-port`
> 改过也不会给出打不开的地址。`/info` 报 `0` 表示 PC 那边压根没开 HTTPS，引导页会把
> 这一条单独摆出来，而不是给你一条死链。

### 怎么用

左上角点「体感」→ 首次会弹授权（必须由点击触发，这是 Apple 的规矩；拒绝过后要先去
Safari 设置里重置该站点权限）→ 开起来后**把 iPad 放平时点一下「校零」**。

- 满行程 = **25°** 偏转，超过就夹在 ±1
- 输出 = 体感 + 杆盘，两者相加再夹住 —— 杆盘还留着当微调，松手回 0
- 转屏会重置基准（`orientationchange`），因为横竖屏的 beta/gamma 角色是互换的
- 方向反了在「校准」页的横滚/俯仰开关里翻，别改代码

### 一个物理上的实话

体感要**拿着平板转**才有意义。11 吋 444g，双手握住时拇指只够得到屏幕两侧边缘 ——
所以体感模式下中间那个大圆盘是够不着的（它这时候也确实只剩读数作用），
油门（最左竖条）、脚舵（左上）、按钮（右上）都在边缘，这才是能摸到的那部分。

如果你发现举着它飞十分钟就累，那就退回触摸模式 —— 这也是我把两者做成相加而不是
二选一的原因：随时可以只关体感。

## 六、链路够不够用：别只看 RTT 均值

底部右边那几个数各有分工，最容易误读的是第一个：

| 显示 | 含义 | 会不会骗人 |
|---|---|---|
| `RTT 1.9 · 峰 2` | 单次 HTTP 往返，客户端侧量的 | **均值会**。EWMA 平滑后偶发卡顿看不出来 |
| `收 50 Hz` | 实际发帧率。掉到 49 表示约 2% 的 tick 被「上一帧还没回来」跳过 | 一般不会 |
| `帧间隔峰 21ms` | **服务端**看到的近 100 帧最长到达间隔 | 不会，这就是摇杆吃到的东西 |

**判据**（2026-11-18 实测基线）：

| 帧间隔峰 | 结论 |
|---|---|
| 21–25 ms | 和环回没差别，Wi-Fi 够用，网线可以不买 |
| 25–45 ms | 能飞，密集机动时能感觉到一点点 |
| > 45 ms 反复出现 | 那是卡顿，得上线 |
| > 80 ms | 别飞，杆会一顿一顿 |

颜色也是按这个分：绿 / 琥珀 / 红。

**环回基线**（127.0.0.1，完全不走网络，等于这套东西的物理上限）：

```
avg 20.0 ms   max 21.5 ms   rate 50.0 Hz   RTT 1.9 ms (峰 2)
```

**iPad Pro 11" 走 Windows 移动热点 + HTTPS 的实测**（就是本机的真实工况）：

```
avg 20.6 ms   max 30.4 ms   rate 48.4 Hz   secure=true
```

Wi-Fi 只把峰值从 21.5 抬到 30.4，帧率掉到 48.4 —— 落在「能飞」那一档，
**不需要买 USB-C 转 RJ45**。真到密集机动觉得不对劲时，先回来看这个峰有没有越过 45。

也就是说 20 ms 一帧是 `setInterval(20)` 的固有条距，不是延迟 —— 别拿它当"网络慢"。
页面刚加载的头一两百毫秒会出现一次 90ms 级的峰，那是首帧和脚本编译，不是链路。

服务端也能直接查，不用盯屏幕：

```bat
curl http://127.0.0.1:8080/input
:: "gap_ms": {"avg_ms": 20.0, "max_ms": 21.5, "rate_hz": 50.0, "window": 100}
:: "secure": true          ← 这一帧是从 https 还是 http 进来的
```

## 七、打不开 / 连不上：先看 `tools/.tls.log`

iOS 在证书不被接受时**不会给浏览器任何提示**，直接在握手层断开，
Safari 只会说「打不开网页」或「已丢失网络连接」—— 这两个词指向完全不同的原因，
照着猜会浪费一整晚。所以 https 侧每次握手都落一行到这个文件（已 gitignore）：

| 日志行 | 含义 | 该干什么 |
|---|---|---|
| `OK ... TLSv1.3` + `REQ ... TLS 200 /yoke` | 通了 | 没事 |
| `FAIL ... SSLV3_ALERT_CERTIFICATE_UNKNOWN` | 握手成功，**客户端不认证书** | iPad 上装描述文件，并打开「证书信任设置」的开关 |
| `FAIL ... [SSL: HTTP_REQUEST] http request` | 对方发的是**明文**，端口讲的是 TLS | 地址栏必须带 `https://`（见下） |
| `PLAIN ... http-on-tls-port` + `200` | 明文请求，被双模端口正常服务了 | 能用，但体感不会有数据 |
| `ABORT ... ConnectionAborted` | 对端自己断开（浏览器预连接取消） | 忽略 |
| **整份日志里没有那台设备的 IP** | 请求根本没到 | 这才轮到查网络/防火墙 |

三个已经踩过的坑，都记在这里：

1. **Safari 对非 443 端口不会自动升 https。** 地址栏只写 `192.168.137.1:8443`
   它会按 `http://` 发，明文打到 TLS 端口上直接被掐 —— 现象就是「打不开网页」。
   现在 8443 **两种都收**（首字节 `0x16` 走 TLS，否则当明文 HTTP 服务），
   任何写法都能打开页面；但体感仍然只有 https 才有数据，左上角那个 `http` 红字就是提醒。
2. **服务端证书有效期不能超过 398 天。** 苹果的硬性规定，超规的连接在握手层被拒，
   同样表现为网络错误。`make-cert.py` 现在签 365 天，并且会自己验、超了直接报错。
   根 CA 不受这条限制，所以**重签 leaf 不需要在 iPad 上重装描述文件**。
3. **TLS 收尾要发 close_notify。** `socketserver.shutdown_request()` 只发一个裸 FIN，
   iOS 的 `NSURLSession` 会把它当成「网络连接已丢失」—— 页面其实已经收到了。

## 八、已知限制

| 限制 | 说明 |
|---|---|
| 没有配平 | 手机端那个配平是直升机用的开关（固定翼默认关），iPad 这版没做 |
| 体感要走 HTTPS | 且要装一次根证书（见第五节）；每次重开页面要重新授权一次 |
| 竖屏 | 不支持 —— 这套版式只做横屏 |
| 断线就回中 | `vjoy_out.py` 的 531ms 看门狗兜底，页面自己 3 次失败会显示 `断开 · 重试中` |

切走/锁屏时页面会**主动把所有输入清零**（`visibilitychange` + `blur` + `pagehide`），
避免恢复时杆量还卡在半路。

## 九、验收

```bat
:: 另起一个隔离端口，别和 iPad 正在用的 8080 抢 /input 和 5010
python tools\start.py --port 18080 --udp-in 15010 --tls-port 18443 --vjoy-port 15011 --no-vjoy mock

python tools\check-yoke.py https://127.0.0.1:18443/yoke   :: 74 项，含体感/上锁/配平/仪表
python tools\check-yoke.py http://<本机IP>:18080/yoke      :: 70 项，验引导页
```

`--udp-in` 必须跟着改：`mock_export.py` 的 `--target` 默认写死 `127.0.0.1:5010`，
`run-all.py` 早先没把这个参数转下去，于是「beacon 在 15010 等、mock 往 5010 发」，
页面上一个数都不动 —— 现在 `--target` 跟着 `--udp-in` 走。

http 那条**必须用局域网 IP**，不能写 `127.0.0.1`：浏览器把 `127.0.0.1` 当"可信来源"，
明文 http 下 `isSecureContext` 也是 true，脚本会走 https 分支去断言 `顶栏标记 https`。

`tools/check-yoke.py` 用 playwright + 系统 Chrome，在 1194×834 的 iPad 横屏视口里**真的发触摸事件**
（CDP `Input.dispatchTouchEvent`），https 下还用 `DeviceOrientation.setDeviceOrientationOverride`
假造倾斜，然后回头查 `/input` 收到了什么：

- 杆盘是正方形、≥400px、推过头仍夹在 1.0、松手回中
- 未碰油门时 `/input` 里**没有** `t` 字段
- 油门 1/4 处发送值 ≈ 0.25（默认反转：发送 = 1 − 手指位置），松手保持；屏上旋钮停在手指位置（显示不反转）
- 机炮按下 = bit11，松开清零
- 脚舵：是横向滑块（宽 > 高×1.5）、右滑 `r` 为正且是比例值、左滑为负、松手回 0
- 四页：四个页签齐全、切到战斗页、**切页后杆盘不挪位**、起降/战斗面板互斥显示
- 仪表页：十个数字都有读数、大姿态球有姿态、该页收起杆盘
- 体感：右倾 15° ≈ x 0.51、前倾 12° ≈ y −0.36、校零回 0、超行程夹 1.0、关掉回 0
- https 下**不弹**引导页；故意占两条哑 TCP 连接，https 仍须 3s 内响应
- TLS 端口同时吃得下明文 HTTP（地址栏只写 `ip:8443` 的那种请求）
- 读数条：有读数、姿态球有姿态、不压底部杆盘、顶部状态行不压杆盘、油门圆徽章不脱轨；标记 https/http 各自正确
- 版位：顶部留出让开状态栏（≥34px）、脚舵贴右下角、脚舵不压按钮列、脚舵不压读数条
- 解锁键：贴左下角（`left≤32`、距底 ≤80、在杆盘左边）、≥96×96、不压油门竖条、不压读数条
- 上锁：默认锁、锁时推杆无输出、解锁后生效、锁时 `t` 消失、解锁后油门值仍在
- 配平：记配平后松手保持、清零后回中
- 按钮快速点按不丢（120ms 脉冲）、脉冲到点自动松开
- 校准页：能进能退、滑块生效、恢复默认；满行程调大后同样倾角的输出确实变小
- http 下点体感弹出整屏引导页，地址等于 `https://<host>:<真实端口>/yoke`，描述文件两个别名都能下载
- 无 console 报错、无元素溢出视口

当前计数：**https 分支 70 项、http 分支 66 项**，全过才算验收通过。
（beacon 要用 `--udp-in 5099` 起，否则读数条那几项会一直等不到帧。）

截图落在 `.tmp/yoke-ipad.png`（横，起降页）、`.tmp/yoke-pfd.png`（仪表页）、`.tmp/yoke-tilt.png`（体感）、`.tmp/yoke-tls.png`（引导页）。

> **注意 localhost 不算数**：`http://127.0.0.1` 在浏览器眼里是安全上下文，
> 拿它测不出「http 拿不到传感器」。要验那条分支必须用局域网 IP（如 `192.168.137.1`）。

> **测试时务必独占 `/input`**：iPad 上开着 `/yoke` 的话，它会和测试页以各 50Hz 交替喂数据，
> 读出来一半是你的值一半是它的值。beacon 会打印 `[input] 操纵量来源 → <IP>`，
> 出现两个来源就是两路在抢。
