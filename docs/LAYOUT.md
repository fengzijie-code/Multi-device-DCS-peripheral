# 外设布局框架

> 适用范围：单人驾驶、Pixel（手机摇杆）+ iPad（辅助面板）这套组合。
> 第一个实例是 JF-17，但下面的判断标准对任何机型都成立 —— 换飞机时只需要重填 §4。

---

## 1. 先划边界：什么东西不该上手机

**手机只替代 HOTAS，不替代 MFD。**

JF-17 是玻璃座舱，三个 MFD 加一排 OSB 软键。那些操作需要盯着菜单、按 3mm 宽的软键，手指在 5 寸屏上根本点不准，而且每点一次都要看屏幕 —— 比鼠标慢一个数量级。

所以边界是：

| 类别 | 归属 | 原因 |
|---|---|---|
| HOTAS 上的功能（杆、油门、扳机、武器切换、锁定） | **手机** | 本来就是为「盲操」设计的 |
| MFD 菜单、OSB 软键、输入框 | **鼠标/键盘** | 需要视觉确认，触摸屏帮倒忙 |
| 一秒变不了几次的读数（油量、温度） | **iPad** | 低频，看一瞥就够 |
| 低频但需要看的（无线电、暂停） | **键盘** | 不占总注意力 |

---

## 2. 三档分层：按「手能不能盲操」分

| 档位 | 判据 | 落点 |
|---|---|---|
| **A · 盲操** | 交战中每秒都用，眼睛不能离开 HUD | 手机，拇指/食指固定位置，闭眼能按对 |
| **B · 余光可及** | 一秒内要按到，但可以瞥一眼 | 手机，稍远的位置 |
| **C · 需要看一眼** | 起降/调构型时才用，不急 | 手机底部一排，或键盘 |

**判断口诀**：如果一个操作在「被导弹追着」的时候要用，它必须在 A 档；如果只在「地面滑行」时用，C 档就够了。

---

## 3. 单人 vs 双人：这是最大的分岔

单人驾驶时，**一个人要同时扮演飞行员和武器官**。这直接决定了 A 档能装多少东西：

- **双人**：A 档只需要飞行 + 发射，雷达/目标交给后座 → A 档可以很克制
- **单人**：A 档还得包括锁定、切目标、干扰弹 → 但人的手只有两只，**必须砍到最少**

所以单人的 A 档只有四件事：**杆、油门、发射、锁定**。其余全部下沉。

> 这也是当初否掉「一个滑块扛五种手势」的根本原因：单人没有余裕去数「滑了几次」。

## 4. 实例：JF-17（单人，Pixel + iPad）

### 4.1 设备分工

| 设备 | 承担 | 备注 |
|---|---|---|
| **Pixel · 起降页** | 杆、油门、脚舵、襟翼↑↓、起落架、配平 | 起降时注意力在外部视景，手可以慢慢摸 |
| **Pixel · 战斗页** | 杆（只显示不碰）、油门、脚舵、武器↑↓、锁定、干扰弹、**机炮 / 武器投放** | 2026-11-13 重排后的实际版面；视角已在 v1.2.0 移除（交给头瞄） |
| **iPad** | 燃油、发动机、构型、配平/舵面、飞行总览 | 一秒变不了几次，瞥一眼就够 |
| **键盘** | MFD/OSB、无线电、暂停、地面开关 | 需要停下来操作的 |

### 4.2 按钮编号（vJoy，已配 20 个）

> 代码里从 0 数，DCS 里从 1 数，差一位。

| 功能 | 常量 | DCS 里 | 优先级 |
|---|---|---|---|
| 襟翼收起 | `FLAPS_UP = 0` | `JOY_BTN1` | 已有 |
| 襟翼放下 | `FLAPS_DOWN = 1` | `JOY_BTN2` | 已有 |
| 起落架 | `GEAR = 2` | `JOY_BTN3` | 已有 |
| 武器上一个 | `WEAPON_PREV = 3` | `JOY_BTN4` | 已有 |
| 武器下一个 | `WEAPON_NEXT = 4` | `JOY_BTN5` | 已有 |
| 锁定 | `LOCK = 5` | `JOY_BTN6` | 已有 |
| 武器投放 | `FIRE = 6` | `JOY_BTN7` | 已有（原「发射」，2026-11-13 语义收窄为投放） |
| 雷达模式 TWS/RWS | `RESERVED_TWS = 7` | `JOY_BTN8` | **预留，待加** |
| 目标上一个 | `RESERVED_TARGET_PREV = 8` | `JOY_BTN9` | 预留（TWS 下才有意义） |
| 目标下一个 | `RESERVED_TARGET_NEXT = 9` | `JOY_BTN10` | 预留 |
| **干扰弹投放** | `COUNTERMEASURE = 10` | `JOY_BTN11` | **已有** |
| **机炮** | `GUN_FIRE = 11` | `JOY_BTN12` | **已有（2026-11-13 新增）** |

> 这张表是设计快照，实际绑键以 **`docs/BINDING.md`** 为准。机炮和武器投放
> 拆成两个键的理由、以及 `BTN7` 需要的迁移步骤都写在那里。

### 4.3 待加功能的排序理由

1. ~~**干扰弹**~~：**已加**（2026-11-12）。被锁定时按一下是生和死的区别，而且它是
   「一次性动作」，不需要连续操作，最适合做成一个大按钮 —— 所以排在最前面先做。
2. **雷达模式 TWS/RWS**：决定雷达怎么扫，应该在**进战前**设好，不该在扣扳机时选。做成一个开关式的按钮，按一下切换、显示当前模式。
3. **目标切换**：只在 TWS 下有意义（RWS 只能锁一个目标）。慢半拍通常还能补救，所以排最后。

## 5. 换机型时怎么套这个框架

只需要重填 §4，前三节不动。步骤：

1. **列 HOTAS 清单**：这个机型真实 HOTAS 上有哪些按钮？（DCS 手册的 HOTAS 章节）
2. **标 A/B/C 档**：按 §2 的口诀分
3. **A 档不超过 6 个**：超过就说明分错了，或者该下沉
4. **检查 MFD 依赖**：哪些操作必须在 MFD 上完成 → 划给鼠标，别硬塞
5. **填按钮编号**：新功能一律**往后追加**，不要重排 —— 一重排，DCS 里绑好的键全废

---

## 6. 判定清单：这个功能该不该上手机

逐条问，有一条不满足就别加：

- [ ] 它在真实飞机的 HOTAS 上吗？（不在 → 大概率不该上）
- [ ] 交战时会用到吗？（只在起降用 → 放底部，或者干脆不用）
- [ ] 能盲操吗？（需要看屏幕才能确认 → 不该放在 A 档）
- [ ] 误触的后果可逆吗？（不可逆 → 必须加长按保护，见 `GuardButton`）
- [ ] 加进去之后，A 档还 ≤ 6 个吗？（超了 → 先砍别的）
