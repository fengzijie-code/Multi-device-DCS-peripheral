# iPad 辅助面板（panel.html）

> 目标：把 iPad 横屏放在桌上，当作 DCS 的**低频辅助仪表**——只看那些一秒变不了几次的量：油量、发动机、构型、配平、总览。
>
> 这块屏是网络实测**降级**之后的产物。为什么不是实时 PFD、为什么可以接受 200ms，见 [`NETWORK-FINDINGS.md`](NETWORK-FINDINGS.md)。一句话版本：校园网被客户端隔离、USB 线在 iPad 上没有 IP 链路、PC 自建热点实测 RTT 416ms，瓶颈是单网卡 STA+AP 时间片轮转，换软件解决不了。既然链路慢，就只让它承载慢的东西。

## 2. 怎么用

### 2.1 启动

日常还是只跑那一个启动器（它会把桥接、看门狗、vJoy 一起拉起来）：

```
tools\start-usb.bat
```

`beacon.py` 会监听 `0.0.0.0:8080`，里面就带着 `/panel`。

### 2.2 iPad 上打开

先让 iPad 和 PC 在同一个网里（目前实测能通的是 **PC 开热点、iPad 连它**，RTT 400ms 级；有线以太网供电那条路还没验证）。然后 Safari 打开：

```
http://<PC的局域网IP>:8080/panel        ← 仪表盘
http://<PC的局域网IP>:8080/             ← 自检页（看通不通、看 RTT）
```

不知道 IP 的话，桥接启动时控制台会把本机地址打出来；也可以在 PC 上跑 `python tools/netprobe.py`。

**加到主屏幕**：Safari 分享 → 添加到主屏幕。这样打开就是全屏、没有地址栏，横屏放着不会误触。页面已经设了 `apple-mobile-web-app-capable` 和 `viewport-fit=cover`，刘海/圆角不会盖住内容。

### 2.3 自检顺序（出问题按这个顺序看）

1. iPad 能打开 `/`（自检页）→ 网络通；打不开就是网络问题，别查面板。
2. 自检页 RTT 数字 → 几十毫秒是正常，几百毫秒说明这条路只配跑慢变量。
3. 打开 `/panel`，看顶部状态行：
   - `在线 · 遥测 60 Hz · 慢变量 300 ms 前` → 全通。
   - `没有数据` + 整页压暗 + 红条 → 桥接活着，但上游没在发（DCS 没进座舱 / Export.lua 没装）。
   - `遥测在线，但没有慢变量` → 你的 `Export.lua` 是旧版，只发 60Hz 主帧，没有 1Hz 包。换成本仓库 `dcs/Export.lua`。

## 3. 数据是怎么流过去的

```
DCS ──LoGet*──► Export.lua
                 ├── 60Hz 主帧  {"t","alt","ias",...}   → 给 Pixel 的 PFD
                 └── 1Hz  慢变量 {"sys":{...}}          → 给 iPad 面板
                        │
                        ▼  UDP 127.0.0.1:5010
                   beacon.py  /state
                        │
                        ▼  HTTP（iPad 每秒拉一次）
                   panel.html
```

**为什么慢变量要单独打一包，而不是塞进主帧：** 主帧 60Hz 是给姿态仪用的，字段越少越好；燃油/温度这类量一秒变一次，混进主帧等于 60 倍冗余。分开之后还有一个额外好处——`{"sys":...}` 不参与 `hz`/`age` 统计，主帧断了立刻能看出来，不会被慢变量拖成「看起来还活着」。

**为什么面板是 1Hz 轮询而不是 WebSocket：** 慢变量本身就是 1Hz，拉得再快也是同一份数据。轮询还能在链路抖动时自己恢复，不用写重连。

## 4. 五张卡片读什么

| 卡片 | 字段 | 来源 | 单位/说明 |
|---|---|---|---|
| **燃油** | 总油量 | `fuel + fuelx` | kg |
| | 内 / 外 | `fuel`, `fuelx` | kg，外部副油箱 |
| | 消耗率 | 桥接算的 | kg/h，取油量窗口首尾斜率（跨度 <3 秒不给读数） |
| | 续航 | 桥接算的 | 当前流量下还能飞多久 |
| **发动机** | 转速 左/右 | `rpm_l/r` | % |
| | 温度 左/右 | `temp_l/r` | °C |
| | 液压 左/右 | `hyd_l/r` | 压力原始值 |
| **构型** | 起落架 / 襟翼 / 减速板 / 座舱盖 / 轮刹 | 主帧 + `sys` | 起落架三态：放下 / 收起 / 运动中 |
| **配平 / 舵面** | 升降 / 滚装 / 偏航配平 | `cs_e/a/r` + 手机杆量 | **估读**，见 §5.1 |
| | 舵面 升/副/方 | `cs_e/a/r` | 度，实时偏角 |
| **飞行** | 空速 / 高度 / 升降率 / 航向 / 过载 | 主帧 | kt / ft / fpm / ° / g |

单位选择跟 Pixel 上的 PFD 保持一致（kt、ft、fpm），两边读数不会互相打脸。

## 5. 三个必须先说清楚的限制

### 5.1 「配平」不是真的配平 —— 是估读

**DCS 的 Export API 根本不提供配平位置。** `LoGetMechInfo()` 里能拿到的是舵面**实际偏角**，那是「配平 + 杆量」的合成值，不是配平本身。

面板的办法：**只在手机杆回到中位的那一刻取一次舵面偏度，然后保持**。

- 杆在中位 → 舵面偏度里没有你的输入，剩下的就是配平顶出来的量。
- 杆一离开中位 → 数字冻结，不再更新（否则一压杆数字就跳，没法看）。
- 卡片底部那行小字会说明当前是「采样中」还是「保持」；摇杆没连上时直接写「判断不了杆是否回中，配平读数暂停更新」。

**它在哪些机型上有效**：全动平尾 / 可配平平尾（F-16、F/A-18、F-15、Su-27 系）——配平直接改变舵面中位，所以杆回中时舵面有非零偏角，读得出来。
**它在哪些机型上会对不上**：传统升降舵 + 配平片（配平片动、升降舵不动），杆回中时舵面恒为 0，面板就永远显示 0°。

> **2026-11-11 实测（免费机全军覆没）**：TF-51D 和 Su-25T 的 `controlsurfaces` 字段都是 `null`，一架都不给。面板会直接写「这个机型不提供舵面偏度数据」，不会拿 0.0 冒充。
> 这意味着**在你目前拥有的机型上，配平这张卡是废的**。要让它活过来只有两条路：① 飞高保真模块（F-16C / F/A-18C / A-10C II，这些才实现 `controlsurfaces`）；② 上 DCS-BIOS 直接读座舱里的配平指示器（P2 的活）。在那之前，这张卡的价值只剩「告诉你这架飞机不提供」。

这是接口硬限制，不是懒。要真配平只有一条路：DCS-BIOS 读座舱里的配平指示器（每机型单独适配），属于 P2 的回控工程。

### 5.2 油量：两种单位口径，面板自己判

导出接口的 `fuel_internal` **单位不统一**，实测两种都有：

| 口径 | 机型 | 表现 |
|---|---|---|
| 公斤 | Su-25T（3170.88 kg） | 正常报 kg，油量条满刻度 = 本次见过的最大值 |
| 0–1 比例 | TF-51D（0.9862 = 98.6%） | 自动改成百分比，满刻度固定 100%，单位显示 `%` |

判据就一条：`fuel <= 1.5` 就当比例。面板会同时把消耗率换成 `%/h`、把说明文字换成「该机型只给油量比例、不给绝对容量」。

公斤口径下的两个已知误差：

- **满刻度 = 页面打开后见过的最大总油量**，所以**刷新页面的瞬间是 100%**，哪怕你只剩两成油。
- 中途加油会让条子按新值重新缩放。

真要精确比例，看数字，别信条子。

### 5.3 消耗率遇到加油/重开任务会重算

桥接发现油量**上升**就清空历史重算（否则斜率会算成一个小得离谱的假数，续航跟着乱报）。代价是加油/重开任务之后的**前 3 秒没有消耗率和续航读数**，显示 `--`。这是刻意的：给个假数字比不给更糟。

## 6. 降级行为（都会显式表现出来，不会假装正常）

| 情况 | 表现 |
|---|---|
| 主帧 2 秒没来 | 整页压暗 + 顶部红条「数据已冻结」 |
| 慢变量 5 秒没来 | 慢变量那几张卡保留旧值但不再更新（`sys` 变 `null`） |
| 手机 / 摇杆没连 | 配平三行显示 `--`，小字说明原因；其余照常 |
| `fetch` 失败 | 状态行变「连不上桥接：…」，圆点变红，整页压暗 |

阈值不同是有原因的：主帧 60Hz，2 秒不来基本就是断了；慢变量 1Hz，卡 2 秒只是网络抖一下，用 5 秒才不会频繁闪成「无数据」。

## 7. 今天验了什么（可复现）

```bash
# 1. 导出端：真实 Export.lua 跑在 Python 嵌入的 Lua 里
python tests/test_export_lua.py                    # 35/35

# 2. 桥接 + 模拟源 + 假手机
python tools/beacon.py --port 8091 --udp-in 5091 --input-out none
python tools/mock_export.py --target 127.0.0.1:5091 --rate 20 --duration 45
python tools/fake-phone.py 8091 45 999

# 3. 渲染验收（三个视口截图 + 逐字段取文本 + 溢出检测 + console 收集）
python tools/check-panel.py http://127.0.0.1:8091/panel .tmp
```

实测结果：

**真机（2026-11-11 上午，DCS 实飞）**

| 项 | 结果 |
|---|---|
| 主帧 | 60.0 Hz 稳定，age 10–16 ms，0 坏帧 |
| Su-25T 慢变量 | `fuel` 3170.88 kg、`rpm` 91.4×2、`temp` 664°C×2、`hyd` 210×2 —— **全部有效** |
| Su-25T 消耗率 | `ff` −2580 ~ −2625 kg/h 稳定，续航 1h 21m，符合该机内油量 |
| TF-51D 慢变量 | 只有 `fuel`（比例 0.9862）和 `rpm_l`，其余全 `null` |
| 舵面偏度 | **两架都 `null`** —— 免费机不实现 `controlsurfaces`，配平卡无数据可用 |
| 杆量 | 手机端 50Hz 同时在发，面板能读到 x/y 并据此判断杆是否回中 |

**模拟源**

- `/state` 里 `sys.ff = -4141.6 kg/h`、`endurance_s = 2760`（46 分钟），与模拟源的 1.15 kg/s 完全吻合——油耗率算法是对的。
- 三视口（1024×768 横屏 / 768×1024 竖屏 / 412×915 手机）**零横向溢出**，console 干净。
- 冻结态验证：主帧一停，整页压暗 + 红条 + 配平小字变「摇杆没连上」，三个降级同时正确。
- 配平估读验证：假手机回中时报 `1.2°`（模拟源的配平偏置 0.021 rad ≈ 1.2°），推到一边后数字保持不动，小字变「保持」。

真机上抓出来的四个坑（都已经修了，记在这里免得重犯）：

0. **缺失字段被伪装成 0** —— `nil` 被编码成 `"0"`，于是 TF-51D 上显示「温度 0°C、液压 0」，看着像设备故障。现在 `nil` 如实发 `null`，面板显示 `--`。这条是这次最重要的修复：**假数据比没数据更糟**。
1. **燃油精度只有 3 位小数** —— 比例机型每秒只掉 0.0002，被量化噪声吃掉，消耗率在 0 和翻倍之间跳。提到 4 位。
2. **「油量上升就清空历史」的阈值写死 1.0** —— 按公斤机型定的，比例机型整个量程才 0–1，永远不触发，换任务后历史混着两次飞行，斜率算成了正数。改成跟量级走。
3. **`canopy` 语义写反了** —— 我按「1 = 关闭」写的，Su-25T 实测飞行中读到 `0.0`（座舱盖当然是关的），说明 **0 = 关闭**。已纠正。

模拟源侧的两个坑：

1. **`.big` 被 `.row .v` 按 CSS 优先级压掉** —— 总油量字号从来没生效过，不报错不报警，只能读计算样式才发现。现在写成 `.row .v.big`。
2. **`mock_export.py` 的燃油单位是 0–1 的比例**，而真实 `LoGetEngineInfo().fuel_internal` 可能是公斤。现在 mock 支持 `--aircraft tf51` 复现「缺字段 + 比例」这个形态，全量机型用默认值。

## 9. 排查表

| 现象 | 先看什么 |
|---|---|
| iPad 打不开 `/panel` | 先开 `/`。`/` 也不通 = 网络问题，跟面板无关 |
| 页面能开，但一直「没有数据」 | DCS 是否在任务里（主菜单不发数据）；`Export.lua` 是否装到正确路径 |
| 有飞行数据，但燃油/温度是 `--` | `Export.lua` 是旧版，没有 1Hz 慢变量包 |
| 配平一直是 `--` | 手机没连（看小字提示），或者该机型读不出配平（§5.1） |
| 配平一直是 0.0 | 该机型是传统升降舵 + 配平片，见 §5.1 |
| 油量条一直是满的 | 页面刚刷新，满刻度被重置成当前值（§5.2） |
| 消耗率/续航是 `--` | 刚加油或刚重开任务，等 3 秒（§5.3） |
| 数字在动但明显慢半拍 | 正常：这是 1Hz 数据 + 1Hz 轮询 |
